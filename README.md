For this project, I was trying to solve the problem of organizing the course information. I approached this problem methodically by analyzing three data structures to solve it which are vectors, hash tables, and binary search trees. Selecting the right data structure is crucial for runtime efficiency, and one may fit another problem better. I chose a hash table as it has an average lookup performance of O(1) and can handle a ton of information. I overcame challenges in this by implementing a trim() function to handle the white space and other potential edge cases from the file input, as well as missing file handling. All of which were handled through troubleshooting and implementing fixes as I tested. 

This project has solidified that not all data structures or algorithms can be used for all. You truly need to take a deep dive into what the end user is actually requesting. It reinforces things I learned from previous classes where a Product Owner (PO) gets into the shoes of the stakeholders and client to see what it is they need to build. It has also evolved the way I write programs to ensure that the changes I make not only make sense, but handle it efficiently. I have now become more attuned to the performance of my own programs, which I used to not worry so much about. I also want to make sure the programs are able to be split apart into reusable pieces, so I don’t have to keep writing the same thing over and over, such as a CSV parser.
